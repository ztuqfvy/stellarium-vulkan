# T30 时间页**视觉层**判据组（2026-09-29）

> 一句话：给 `TIMEUICHECK` 追加 **8 条视觉层判据（UI-17..UI-24）**，把"控件存在但
> **看不见/点不到**"这一类缺陷从"只能人工看"变成"可复跑"；**产品代码零改动**
> （纯仪器）；负控用四个扰动证明其中 5 条判据**真的会翻转**。
>
> 交付物出处：A4 移交清单 —— *"QML 交互级测试：时间页新增控件的视觉层 ⬜ 仍待做"*。
>
> 判据数：`TIMEUICHECK` **19 → 27**（既有 19 条口径**一条未改**）。
> 退出码沿用约定：0=PASS / 10=FAIL / 6=UNAVAILABLE。

---

## 1. 为什么需要这一组

`TIMEUICHECK` 既有 19 条（T19 的 UI-01..UI-11 + T22 的 UI-12..UI-16）断言的全是
**数据面**：

* 锚点找得到（`findChild(objectName)` 非空）；
* 值对不对（`SpinBox.value`、`Label.text` 与 C++ 侧逐位比对）；
* 点击有没有落到引擎（投递真实鼠标事件 → 断言引擎 JD/速率/时区**精确**改变）。

它们对**"控件存在、但看不见或点不到"完全无感**。而 Qt Quick 最典型的布局缺陷正是
这一类 —— 本仓库已经真金白银踩过其中一条：**T22 全量首跑实测到 `207×0` 的"布局前
尺寸"**（健康时 `934×341`），照它算坐标投递点击就是空点。

T30 把下面六类变成**可复跑判据**：

| # | 缺陷类 | 症状 | 归到哪条判据 |
|---|---|---|---|
| ① | 零尺寸 | 控件在、宽或高为 0 | UI-17 |
| ② | 被祖先裁掉 / 溢出面板 | 右列按钮跑到页外、压到边框上 | UI-18 |
| ③ | 叠在一处 | 布局塌陷，所有控件堆在 `(0,0)` | UI-19 |
| ④ | 不可见 | `visible=false`，或某个祖先把整支子树隐藏 | UI-20 |
| ⑤ | 文本为空 | Label 画出来是一片空白 | UI-21 |
| ⑥ | **点不到** | 透明覆盖层 / z 序错 / 被兄弟盖住 | UI-22 |
| ⑦ | 前景 ≈ 背景 | 文字"存在但读不到" | UI-23 |

判据自己的正确性由 **UI-24（纯逻辑腿）** 背书 —— 三个自写函数用**已知输入 ⇒
已知输出**验算。没有这条腿，任何一个函数写成 `return 21.0` / `return true`，
上面那一串会在**任何**输入下全绿，而"全绿"看起来毫无破绽（血泪第 8 条）。

## 3. 手法与纪律

与既有 19 条同一条纪律：

* **只读原始量，不复刻被测逻辑**（血泪第 4 条）：`mapToItem` + `width/height` +
  `isVisible` + `text/color/contentWidth`，全部是 QQuickItem 的**原始属性**；
* **采一次快照**（相位 22），后续相位只读快照 —— 免得判据读到一半被布局改掉
  （UI-17/18/19 的矩形都取自快照；UI-22 走实时命中测试，因为它必须反映"当下谁在最上"）；
* **不改产品代码**：页面/面板一律沿**父链**取（不新增一个 QML `objectName` 锚点）；
* **门/扰动放在断言之前**：负控扰动打在相位 22 的**开头**，UI-01..UI-16 早已跑完
  （所以脚本能断言"既有 19 条在负控里零 FAIL"）。

## 4. 四个设计决定（含两条被否掉的）

### 4.1 🔴 `QQuickItem::childAt()` 给不出可用结果 ⇒ 自写下降

UI-22 的第一版直接调 `root->childAt(x, y)`，结果 **20/20 全部落空**。加了探针才看清：

```
根类=QQuickRootItem(MainWindow) 根960×640 直接子项=1
靶中心(root)=52.5,488.0 → childAt=QQuickControl(ApplicationWindowContentControl)
pageStack.childAt(52.5,400) → TimePage_QMLTYPE_36(-)      ← 只下降一层
```

即：在本工程的 `ApplicationWindow` 窗口结构下
（`QQuickRootItem(MainWindow)` → `QQuickRootItem/ApplicationWindowContentControl` →
内容项），`childAt` **只下降一层就返回容器本身**，而不是那个按钮。既然它给不出可用
的结果，就自己走一遍下降（语义按场景图来）：

* 只考虑 `isVisible()` 的子项；
* **子项顺序的反向 = 叠加顺序**（QML 里后声明的画在上面）；
* 命中即递归；都不命中返回 `self`；
* ⚠️ 刻意**不**建模 `z` 与 `clip` —— 本页没设过 `z`，而"超出父边界"已被 UI-18 断言。

并把"**每层选谁**"抽成纯函数 `uiHitPickChild()`，由 UI-24 用已知输入验算
（父 100×100、子 A(0,0,50,50)、子 B(25,0,50,50) ⇒ 点 (30,25) 必须命中**下标 1**）。
不抽出来，这套自写逻辑就只能靠"跑起来看着对"背书。

### 4.2 🔴 UI-22 从"文本不截断"换成"命中测试"：恒真的判据就是假绿

第一版的 UI-22 是"文本未被截断"（`width − contentWidth` 够不够）。首跑读数：

```
余量 px  UT:0.7 JD:0.9 MJD:0.6 历法:0.3 速率:0.4 方向:0.7
```

**六行的余量全都不到 1px**，看着"很稳"—— 理由也硬：`QQuickText` 的
`implicitWidth = ceil(contentWidth)`，而 Label 没设 `Layout.fillWidth` 时布局给的
就是 `implicitWidth` ⇒ 这个差值**本该**落在 `[0,1)` 的取整区间里。

**但把负控打开（月框 `height→0`）之后，同一批读数变成**

```
余量 px  UT:0.7  JD:102.0  MJD:0.6  历法:0.3  速率:0.4  方向:0.7
```

—— **同一个量，一个语境下全都 <1px、另一个语境下跳到 102px。** 而且它在**同码不同跑**
之间也不稳（另有一跑读到负值 `UT:-2.2`、`速率:-5.6`；那次没单独留档，仅作定性提示）。

⇒ **这个量两头都不适合立阈值**：正常态是 `[0,1)` 的取整余量（对"有没有被截断"**没有
分辨力** —— 它恒 <1px），一旦那一行被布局挤压或拉伸就跳到任意量级（负值 = 文本宽于
自身 item、会被裁；正的偏大值 = item 被拉开）。正是血泪第 4 条说的"孤立断言可假绿"。

顺带把这条 note 的措辞也改准了：初版写的"**恒为** [0,1) 的取整余量"是**为当时的
读数背书**（血泪第 7 条的轻量版）；现在写"**只作读数、不判** —— 宽度未被布局约束时
是 `[0,1)` 的取整余量，一旦列宽被挤压就变成任意负数"。

处置两条腿：

1. 这一类**降级为读数**（打 `VIS-note`，不判）；
2. UI-22 换成**中心点命中测试** —— 它是本组里**唯一**能抓住"透明覆盖层 / z 序错 /
   被兄弟盖住"的判据（矩形检查对这三类统统无感），而且**负控会翻转它**。

### 4.3 对比度阈值取 2.0：回归护栏，不是重新评审设计

WCAG 对正文给的是 4.5:1（非文本 3:1）。这里**刻意取 2.0**，理由写在代码注释里：

> 本判据的职责是**回归护栏**（抓"前景被改成与背景同色"这类真实缺陷），不是重新评审
> 设计。产品里几处浅灰说明文字本来就低于 AA，按 4.5 判会把**既有的设计选择**判红
> —— 那不是本任务要的。

达标情况作为**读数**一并打印（`≥4.5 的 7 项、≥3.0 的 7 项`），供人工评审。
只纳入**声明了 `color`** 的 7 个文本行 —— `Button/CheckBox/ComboBox` 的文字底色由
style 绘制、读不到 `color`，**明确不纳入、不假装覆盖**。

### 4.4 产品代码零改动

原计划想给 `TimePage.qml` 根加一个 `objectName: "timePage"` 当锚点。改为
**沿父链取矩形**后不再需要：`uiAncestorOverflowDetail()` 逐级比对**更强** ——
它同时覆盖"跑到页外"和"溢出自己所在的面板"两种越界，一个 QML 锚点都不用加。
⇒ 本轮改动面 = `src/ui/main.cpp`（纯仪器）+ 脚本 + 文档。

## 5. 负控（四个扰动 ⇒ 5 条判据翻转）

`STELQUICK_TIME_VISUAL_NEGCTL=1` 让套件在**跑完 UI-01..UI-16 之后**故意破坏四个
视觉事实。**只扰动观测面，不改产品代码**：

| # | 扰动 | 打中的判据 | 为什么"打得到" |
|---|---|---|---|
| ① | 月框 `height → 0` | UI-17（**有时连带** UI-22） | 布局的 polish 要等事件循环**下一拍**才改回去，而采集就在**同一同步块**里。连带 UI-22 与否取决于该次采集到的矩形（实测两跑：一次 UI-22 落空 1 个、一次 2 个）——**判据只看"有没有翻转"，不把落空个数写死** |
| ② | 年框 `visible → false` | UI-20 / UI-22 | `visible` 不是布局管的属性，改了就一直有效（隐藏项在自写的下降里被 `isVisible()` 过滤掉） |
| ③ | JD 行 `text → ""` | UI-21 | `setProperty` 赋给**带绑定**的属性会**解绑**，300ms 轮询改不回来 |
| ④ | 状态行前景色 → 它自己的有效背景色 | UI-23 | 同上（`color` 绑定被解绑）；对比度 = 1.00:1 |

**负控读数（macOS）**：

```
判据 22/27   VERDICT=FAIL   rc=10
FAIL 的恰好是：UI-17  UI-20  UI-21  UI-22  UI-23
既有 19 条（UI-01..UI-16）FAIL 命中 = 0      ← 扰动在它们之后，零泄漏
UI-18 / UI-19 = OK                          ← 设计如此，见下
```

* **UI-18/UI-19 为什么预期是绿的**：它们的几何取自**下一拍**的矩形，那时布局的
  polish 已经把 `height` 改回去了。它们的正确性由 **UI-24 的纯逻辑腿**背书
  （`uiRectInside` / `uiIntersectArea` 用已知输入验算）—— 正是 T21 那套
  "纯逻辑腿 + 活引擎腿"的两条腿分工。
* **"既有 19 条零 FAIL" 是要断言的**：如果这里出现 FAIL，说明扰动泄漏到了前面的
  相位（仪器污染被测），脚本记 `negctl-BAD` 并以非零退出。

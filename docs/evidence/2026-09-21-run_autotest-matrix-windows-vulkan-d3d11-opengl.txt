【背景：为什么需要这份原始输出】

 开发组复核指出，旧版 run_autotest.cmd 的 matrix 模式——即产出"三后端全 PASS"
 这条结论的入口——自身有两处缺陷，导致该结论在修复前不可信：

   (1) setlocal 未开启 EnableDelayedExpansion，却在 for 块内读 !ERRORLEVEL!，
       逐后端退出码被打印成字面量而非实际值；
   (2) 块尾无条件 set RC=0，于是无论成败都报 "EXIT CODE = 0"。

 两者叠加 = 永久绿灯。已在 d717056 修复。本文件用修复版重跑并原样留档，
 使"三后端全 PASS"这一结论落到可复核的原始输出上，而非仅有一份结论矩阵。

【采集过程中另行发现并规避的"证据污染"问题（同属工具缺陷）】

 .cmd 文件被 cmd.exe 按 OEM 代码页(936/GBK)逐行解析，即使中文只写在 rem 注释里
 也不安全：误解码后的字节可能跨行拼接，残余片段会被当作命令执行，往 stdout
 灌入 "'xxx' is not recognized as an internal or external command" 之类噪声。
 旧版 run_evidence_matrix.cmd 即因此会在写出文件前直接中止。
 另有 chcp 自身会打印本地化版权横幅（CP936 字节），把两种编码混进本应纯 UTF-8
 的流，使文件无法用单一编码解码。

 规避方式（已落入仓库）：
   - 仓库内所有 .cmd 一律只用 ASCII 注释（含 run_autotest.cmd 本轮已清理）；
   - 代码页由父进程预先设好，不在捕获作用域内调用 chcp。
 下方第一段输出已确认 0 行污染。
